# 小批迭代计划核对

按Skill Refiner管理观察和修改假说，按Task Final Review核对计划覆盖。
完整重读原始prompt.txt，并以本轮后续讨论替代原全量队列阶段。

| 要求 | 处理 |
|---|---|
| 先检验方法，不作深度工程分析 | 沿用简洁树与具体候选，知识和工程缺口单列 |
| 每轮6至7题，结束后停 | round-01固定7题，无全量排队机制 |
| 先试解再揭答 | 两个独立冻结阶段，主Agent揭答前生成答案文件 |
| B类复盘并提炼共性 | comparison逐项改动，主Agent核对并归入观察台账 |
| 观察可暂存，不急改Skill | 项目learnings集中管理，T07-H1/H2为collecting |
| 不局限增加规则 | 支持改写、强弱调整、限定、合并和删除 |
| 后续回归可检查及撤回 | 固定版本、保留前后diff，归因后由用户决定 |
| 每轮按案例、按方法汇总 | 两份本轮短汇总，链接具体报告 |
| 当前目录只公开文本 | 私有材料和预登记答案放_private，答案揭答后只公开摘要 |
| Git按任务拆分 | 计划协议与本轮结果分开提交，统一validation前缀 |

过程限制：使用协议隔离，不能排除模型已有记忆。
资源分析单独阶段可提供新增机制的时序证据，不足以单独证明其因果增益。
一题一Agent，不做重复采样，不能量化搜索波动或总体成功率。
本轮不会因B类存在就设计或实施一组Skill补丁，先呈现事实和归因。
