# 小批案例解题协议 v1

适用于round-01。用户要求简洁分析，豁免Skill常规审核子Agent。
不启动子Agent，不改Skill，不提交Git，不阅读其他题或本项目汇总。
不联网搜索答案。文件访问是协议隔离，不宣称操作系统强隔离。

## 允许的材料

第一阶段只读本协议、分配的question.md，以及以下六份当前文件：

- [CCA主文件](../../../../skills/causal-chain-analysis/SKILL.md)
- [CCA因素定义](../../../../skills/causal-chain-analysis/references/factor_definition.md)
- [PMA主文件](../../../../skills/purpose-means-analysis/SKILL.md)
- [PMA情景](../../../../skills/purpose-means-analysis/references/scenarios.md)
- [PMA节点定义](../../../../skills/purpose-means-analysis/references/node-definition.md)
- [PMA展开策略](../../../../skills/purpose-means-analysis/references/expansion-patterns.md)

不要读原书、inventory、pilot、retrospectives、learnings、其他题、答案文件或聊天历史。
以主Agent的具体阶段消息为准，一次只完成被授权的阶段，然后结束等待。
可以用通用领域知识，关键知识前提注明已知/猜测/待核验。
必要事实缺失先报告，不自行搜索可能泄露答案的案例。

## 方法路由

已有系统缺点先CCA，追客观因果与必要条件，再从可干预处生成具体候选。
新功能或整体替换先PMA，从正向功能展开工作原理，区分And与Or。
CCA干预点需要新功能可转局部PMA，PMA候选出现缺点可接CCA。
因果树和目的手段树分别写，注明衔接，避免把两种关系混成一棵树。
CCA树不是具体解法，本测试额外要求从分析提出候选并记录转换。
不引入未授权补丁，不把其他TRIZ工具的贡献默认为这两个Skill的能力。

## 阶段一：CCA/PMA

只写本题目录的before-resource.md，然后停止等待冻结。
包括：熟悉程度（未识别/可能见过/明确记得）、所读材料、任务与硬约束、
方法及路由理由、简洁树、具体候选S1起编号、候选的约束与知识前提、
暂缓方向和停止理由、两轮简短自查。
约15至35节点、4至8候选是规模参考，不强制凑数。
若熟悉具体答案，如实写出记忆可能贡献，不压制正常联想。
本阶段不额外执行系统化资源清单。自然使用题干资源允许，明示其来源。

## 阶段二：资源分析RA

主Agent确认阶段一已冻结后，方可执行本阶段。
读取自己的冻结稿，按物质、能量、信息、空间、时间、环境性质作一次简短补扫。
区分题干直接资源、常识可推资源和新增引入资源。
逐条说明资源的性质怎样服务某个子目的，提出具体增量候选，或明确无增量。
写before-answer.md，引用原有S编号，新增从下一编号起，禁止修改before-resource.md。
标明新增究竟来自资源视角、知识回忆还是其他工具。
此RA为操作约定，不声称完整复现ARIZ。完成后再次停止。

## 阶段三：揭答及复盘

主Agent确认第二阶段冻结并明确开放answer.md后才读它。
写comparison.md，禁止修改两个冻结稿。

- 逐一对照参考的核心机制与冻结候选，具体到转换、构件、操作和读出。
  “用磁”“用光”“改变材料”等宽泛方向不算机制命中。
- 分类A：答案前已含核心机制，分A-CP（阶段一）和A-RA（阶段二新增）。
  B：未预先覆盖，但揭答后有值得尝试的完整路径。C：目前仍无解释力。
  U：题解条件不足，不能判。复合题分子目标记录，避免部分命中冒充全命中。
- 熟悉度独立备注，不用A-memory作为类别，也不推断存在提前泄答。
- 原书机制覆盖、可行替代方案、完整工程验证分开。
  有疑问可给参考答案附不确定性，不把历史方案视作已核验事实。
- B类写原节点/展开→新节点/展开，逐项区分知识、展开轴、优先级、
  边界或桥接层变化。说明从题干出发为何值得尝试，不只把答案反挂到树上。
- 对照已有Skill具体节名，已有要求未执行不能直接说缺规则。
  再给可能缺失的通用操作、触发与排除条件、一个跨域正例及一个误用反例。
  事实、归因假说、修改建议分开。允许结论是证据不足，先观察。
- C类优先诊断知识、执行、预算、任务边界，单题失败不证明方法不适用。

comparison保持便于审阅的篇幅，通常80至160行即可，必要时另附短复盘。
不设计或实施Skill补丁，原始事实足以让主Agent归并观察即可。
