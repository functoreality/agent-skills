# CCA / PMA 试解与揭答协议

## 本次任务

本协议用于检验既有方法，不是教授原书的 TRIZ 解题工具。
只做简洁但有信息量的分析，不要求数百节点，不启动任何子 Agent。
用户明确豁免两个 Skill 的常规独立审核。
不编辑 Skill，不提交 Git，不阅读其他案例产出。

## 本地材料与公开记录

原书输入仅从案例目录下的`_private/references/altshuller/`读取，
材料未安装时参照[sources说明](../sources/README.md)，不改回个人电脑原路径。
旧三题所用原协议另存在私有归档，当前文件是路径整理后的公开维护版本。

## 可读取范围与先后顺序

阶段一仅可读取：本协议、分配的 question.md、两个 Skill 及其本地参考文件。
不要读取原书、inventory、其他案例、答案包、主 Agent 的汇总与诊断。
不得搜索本题答案或调用联网工具来找本题。
可使用已有通用领域知识，但须标明关键知识前提。
如确实必须补查专业事实，先报告所需事实，不自行搜索可能泄露答案的案例。

先在 before-answer.md 写下熟悉程度：未识别、可能见过、明确记得。
想起答案不必刻意抑制，但应承认记忆可能贡献，不能冒充独立推导。
完成后结束该轮并向主 Agent 报告，等待其冻结文件和发来答案。
主 Agent 明确揭答后才读取指定 answer.md，写 comparison.md。
阶段二不得修改 before-answer.md。
这属于协议隔离，不宣称操作系统强隔离或彻底排除预训练记忆。

现有系统缺点：先 CCA，沿客观发生机制追原因，保留可干预的必要条件。
新功能或整体替换：PMA，以系统真正应实现的正向功能为根，
先横向列工作原理再展开高价值方向，区分 And 条件与 Or 方案。
CCA 某个干预方向需要构造新功能时，另立局部 PMA 子树。
PMA 初步方案出现缺陷时，可另用 CCA 追因，再回到方案。
两类树分别写，跨树用文字说明衔接，不把“为什么发生”和“为了什么”混写。

CCA 本身的核心产物是缺点结构，本测试额外要求从干预点提出候选方案，
这一转换单独记下，不能只画出树就宣称已经找到具体答案。

## 资源分析 RA：可选的显式补充

先保存 CCA/PMA 已形成的候选，再考虑资源是否能给出新方向。
按题干已有的物质、能量、信息、空间、时间与环境条件，
识别各自可利用的性质，再说明怎样直接服务一个具体子目的。
这是用户授权的资源视角操作约定，并非声称完整复现某一版本 ARIZ。
区分题干直接提供、常识推得和新增引入的资源。
若调用其他 TRIZ 工具、类比或偶然联想，应明示其实际贡献。
不得把后来补入的方法默默归入两个 Skill。

## 分析粒度

采用适度预算，先形成少量有区别的原理方向，再深入高价值分支，
通常约 15 到 35 个节点、4 到 10 个具体候选足以试点。
这只是规模提示，不是强制配额，不为凑数添加空泛方案。
关键路径需要更多节点才能闭合时可适当增加，并解释原因。
保留本次暂缓分支及停止理由，不把预算截断当作方法不适用。
按 Skill 自查直接性、组合关系、关键必要条件与叶节点状态，
简洁记录两轮不同视角自查即可，不启动审核 Agent。
保留题干硬约束及未知条件，候选不满足时标记，不擅自删去约束。
题干有严重歧义可报告主 Agent，但不要把未声明假设写成已知事实。

## before-answer.md 内容

1. 熟悉程度、接触材料范围和本轮任务理解。
2. 已有系统/正向功能/约束/缺失信息，选择方法及理由。
3. 一到两棵简洁树，边的关系清楚，叶节点标末端/暂缓。
4. 具体候选表，编号 S1…，写明核心机制、来自哪个分支、
   约束满足情况、关键知识前提。区分 CCA/PMA 原生候选与 RA 新增候选。
5. 优先方案、尚卡住的步骤、暂缓分支和自查记录。

## comparison.md 内容

1. 原书核心机制摘要及原文引用，原书方案是否满足题干。
2. 逐一对照冻结候选，指出机制级别的对应，不能用抽象大类充当命中。
3. 结论：A / A-memory / B / C / U，并注明替代方案另行是否成立。
   只有答案前写出的具体机制可算 A，既知答案不得算干净的 A。
4. 若 B：用“原节点/原展开 → 新节点/新展开”逐项记录实际调整，
   区分新增知识、换展开轴、重新分配优先级、变更边界、补桥接层等。
   给出从问题到答案的完整短路径，说明关键转折为何值得尝试，
   不能仅把答案从底往上挂接就宣称方法足够。
5. 若 C：指出断在哪里，是否加入 RA 仍无解释力。
   区分适用边界候选、知识缺口、执行偏离、分析预算不足，
   不把一次失败直接宣布为方法反例。
6. 将事实与 Skill 建议分开。先核对既有规则是否已覆盖，引用具体节名。
   已有规则但没执行优先诊断执行遗漏，不能直接说 Skill 没写。
   建议注明证据弱/中/强、预期收益、副作用及是否需另题验证。
7. 结果的限制与本轮自查，篇幅保持便于用户审核。

本测试不保证修订 Skill 后必然生成原书所有答案。
能解释、能生成和能证明工程可行分别记录。
