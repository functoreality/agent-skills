# 小批案例迭代计划

本计划依据最新讨论替代[原计划](plan.md)的第四、第五阶段。
原始需求和已冻结试点保留，不回写历史结果。

## 每轮流程与停止点

1. 每轮选择6至7道未试解的新题，固定题干、评分要点及Skill文件指纹。
   本轮为round-01，共7题。选题兼顾任务差异，不用于估计总体成功率。
2. 每题一个无历史上下文Agent，先只读题干、当前Skill和解题协议。
   CCA/PMA候选完成后主Agent冻结，再开放资源分析RA，冻结其增量后才揭答。
   两阶段均可记录没有新增候选，禁止为配额拼凑方案。
3. 揭答后对照具体机制，B类逐项复盘实际修改，区分知识、执行、
   策略、预算及题干问题。主Agent独立核对分类与候选的具体程度。
4. 更新按案例、按方法组织的两份本轮短汇总，合并观察但保留各自来源。
   按Task Final Review核对需求、冻结、引用、推理及公开材料。
5. **每轮交付后停止，等待用户确认。**没有修改建议也停止。
   用户可以要求继续观察、批准指定Skill修改，或直接授权下一轮。
   不设置全书并发队列，不自动推进下一轮。

## 观察放在哪里

[learnings目录](../learnings/README.md)作为本项目唯一的候选观察入口。
这里集中管理CCA/PMA组合使用中的事实、假说、反证与后续状态，
比散写到两个Skill更便于关联同一案例，也避免未采纳规则进入解题上下文。
Skill目录只在用户批准具体改动后接收通用规则及必要简例。
无需在多处重复维护同一份候选，Skill若未来需要索引，可链接本项目。
解题Agent不得读取观察台账、先前复盘或尚未批准的补丁。

## 观察到修改的决策

- 观察与归因分开。先记录冻结候选遗漏什么、揭答后实际调整什么，
  再检查既有规则，判断是否真是指令问题。
- T07-H1/H2保持待观察，本轮不启用。既有推演不算独立解题证据。
- 不用固定命中次数自动升级。多个高度相似的同书案例只支持同一机制族，
  不能当作跨领域验证。记录案例数、机制族、反例与未验证项。
- 清楚的小错误且风险很低，可单例提出讨论。其余优先等待独立复现，
  并考虑触发条件、误触发、反证及额外搜索成本。
- 改动可以新增、改写、增强、降级、限定、合并或删除。
  先检查旧要求是否误导，不以追加相反规则抵消旧规则。
- 候选可以停留在收集中，也可升为待讨论、已采纳、已修订或已撤回。
  状态与置信度分别记录，合并观察不抹去原始证据。
- 三项以上独立改动先呈现归因供用户筛选，不直接设计一大组补丁。

## 版本与副作用

每轮固定Skill及参考文件哈希，轮中不改Skill。
每次经批准采纳时记录批准内容、实际diff、前后指纹、适用范围和回退信号。
新版本只用于其后的新轮次，不以新规则重写旧轮次的结果。
不同版本的结果分开列示，不能用未经控制的前后成功率声称改进有效。

后续失败先登记回归疑点，核对题干、知识、执行、预算和搜索随机性。
必要时另行安排旧/新规则的匹配比较，不能仅凭新版本失败认定改动有害。
有证据时提出收窄、改写或撤回方案，由用户确认后执行。
已知同题重试也须注明答案熟悉，不能充当干净盲测。
