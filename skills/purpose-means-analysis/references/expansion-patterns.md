# 节点类型与常用展开范式

目的手段链不要求每个节点都属于唯一类型。这里的分类只是在当前节点
选择本轮展开关系时提供思路，不是强制标签体系。
同一节点在不同阶段可以采用不同范式，
但同一组兄弟节点应采用同一种关系轴。

阅读时按当前问题选择对应章节：

- 拆条件或必要性质：属性状态、具有性质的对象
- 找实现方向：科学效应或方案大类
- 细化既有方案：具有性质的对象、输入输出变换、选择与实施条件
- 构造判断过程：测量、判别或评估

## 1. 属性状态

节点表示希望现有对象或系统达到的状态，例如“使预测误差降低”。
这类节点适合作为实现上层正向功能所需的子目的。
如果用户的任务只是改进已有系统的这项属性，
而不是构造新系统或替换原系统，则不应将它作为本 Skill 的根。

可尝试：

- 用定义、公式、必要条件拆出更直接的子目的
- 区分不同成分、不同作用位置或不同失效形态
- 列出能使该状态改变的工作原理或方案大类
- 转化为“构造具有该性质的新对象”

前两项通常是在拆实现条件，后两项通常是在生成方案方向。
不要把两类结果写成同一组兄弟节点。

公式用于发现目标结构和条件，其变量不自动等于可实施手段。
将公式项写入链中前，仍要说明它与父目的的直接关系。

例：

```markdown
* 获得准确的映射
	* 使训练样本上的误差较小
	* 使新样本上的误差较小
```

## 2. 具有性质的对象

节点表示需要获得某一类对象，例如“构造满足边界条件的数值解”。

可尝试：

- 拆对象必须具备的性质
- 为各性质寻找充分条件或等价条件
- 缩小对象类型、选择对象结构或参数
- 引入中介对象，使其传递所需性质
- 分析对象的构造、制造或求解过程

对象的组成部分通常是 And，但每一组成部分内部可能还有 Or 方案。

## 3. 输入输出变换或功能系统

节点表示把输入变为预期输出，例如“由观测数据重建状态”。

可尝试：

- 明确输入、输出和输出应满足的性质
- 拆所用工作原理、映射表示、必要输入和执行过程
- 将“构造变换”改写为“构造满足性质的对象”后继续展开
- 区分数学层的求解问题与工程层的实际执行实现

不要仅因实现上调用某算法，就跳过它所解决的数学问题或中间变换。

## 4. 科学效应或方案大类

节点表示一类可替代的工作原理，例如“使用电化学方式削弱附着”。

可尝试：

- 按不同科学效应、基本机制或对象作用方式列举 Or 分支
- 从抽象方案逐步具体到候选方案、可执行方案
- 继续分析每个方案所需对象、资源、控制参数和实施过程

抽象方案大类用于限定下一步在哪个方案空间中继续搜索，
不要求当层已经给出可执行做法。把它写成带动作和对象的限定性手段，
例如“采用电学作用改变表面附着”，并标记 `：方案大类`，
不要只写“电学”。

同一层方案大类应处于接近的抽象层级，并尽量形成有区分度的搜索区域。
一个方案大类下面可以继续按效应、对象作用方式、结构、类型和参数逐层缩小。
若某大类本次不展开，还应标记 `；暂缓（理由）`，不能把它当作末端方案。

开放方案空间没有可证明的完全枚举。重点是先列出有差异、有启发价值的
方案大类，完成本层横向骨架后，再优先深入有希望的分支。

## 5. 测量、判别或评估

节点表示获得某性质是否成立的判断，或获得某个量的取值。

可尝试：

- 细化被评估对象及其关键性质
- 细化判别标准、距离定义或可观测信号
- 列出测量原理、数据来源和判别过程

评估通常服务于更高层目标，不应与被评估对象本身混为同一个节点。
只有当前父目的本身是“获得判断或测量结果”时，
测试和评估行为才属于主树中的实现手段。
若测试只是目的手段链完成后的用途，另行生成测试计划。

## 6. 选择、参数化与实施条件

节点表示在候选对象、方案或参数之间作具体选择，或使某方案可实施。

可尝试：

- 区分设计选择、类型选择与参数选择
- 把实现方案所必需的资源、组件、数据或环境条件作为子手段
- 让资源信息影响该分支的展开优先级，但不把它提前并入根本目的

若继续展开只能追问“为什么偏好这个选择”，且用户未要求决策论分析，
可标为 `：暂缓（待用户决策）`。

## 拆分顺序不唯一时

同一目标有时可以先从宏观结构拆，也可以先从直接中间状态拆。
选择更有利于看清后续方案宽度、避免跳步、保持树易读的版本。
若两种视角都重要，可将其中一条作为独立子树，而不强行混在同一层。
