# 目的手段链分析 Skill

## 概述

目的手段链分析从一个尚待实现的根本目的出发，逐层回答：

> 为实现这一目的，直接需要完成什么？

右侧手段实现左侧目的。分析结果通常写成一棵以根本目的为起点、
向下展开手段的树形 Markdown 大纲。

它适合生成或理解系统设计方案，而不是追溯已发生缺点的客观原因。
若已有系统存在缺点，可先用因果链分析确定关键缺点，
再把原系统本来要实现的目的作为本 Skill 的根，探索替换性方案。

本 Skill 保留因果链分析的逐节点展开、优先队列、即时检查、
独立子树和收尾复盘。区别在于，手段空间通常开放，
不要求穷尽所有可能手段，只在当前抽象层级尽力列出有价值的方案大类。

## 何时使用

典型用途包括：

- 从根本目的出发，设计全新系统或生成候选方案
- 为解决已有系统的缺点，重新分析该系统本来应实现的目的，
  以寻找可替代的系统
- 拆解论文、算法或已有方案，看清每一层手段服务的目的与结构合理性
- 为测试、排障或设计评审，拆出系统预期功能所依赖的关键手段
- 围绕某一领域主题，建立目的组织、手段展开的知识框架

各用途共用本文件的核心流程，但展开宽度不同。
遇到论文解读、测试排障、领域框架，或无法判断应探索多少候选方案时，
先阅读 `references/scenarios.md`。

## 核心输出

创建一个 Markdown 文件，以 Tab 缩进表示层级。
缩进下一层的节点是上一层节点的直接手段或直接子目的。

```markdown
# 目的手段链分析：[根本目的概括]

* 获得可用于预报的准确模型
	* 构造能表示目标规律的映射
		* 采用神经网络表示映射：or
			* 使用卷积网络
			* 使用注意力网络
	* 使模型参数反映目标规律
		* 定义能评判模型输出的损失函数
		* 使用优化算法更新参数
```

书写约定：

- 节点优先写成清晰的动宾短语，或“使对象达到某性质”的短语
- 同级节点默认是 And，表示这些手段需共同完成
- 可替代的方案在父节点后标记 `：or`
- 可表达为求和、乘积等明确关系时，可标记 `：+`、`：×`
- 不使用 UID。共享手段和回路均用纯文字引用，见“重复、共享与环路”

## 分析流程

### 步骤 1：理解任务并确定根本目的

1. 识别用户真正希望实现的结果，而非过早锁定某一既有方案
2. 将根本目的改写为清晰、具体、可继续展开的节点表述
3. 若用户给出的是已有系统或缺点，区分两种任务：
   - 要解释缺点为何出现，使用或先使用因果链分析
   - 要用新系统实现原本应有的功能，将该功能作为根本目的
4. 根本目的不必预先附带资源、成本或可行性限制
   这些信息通常属于具体手段的实施条件，或用于调整展开优先级
5. 根本目的存在重大歧义，或用户实际关心多个彼此独立目的时，先确认

### 步骤 2：初始化分析文件与待展开队列

1. 立即创建分析 Markdown 文件，写入根本目的
2. 在记忆中维护待展开节点队列，初始仅包含根节点
3. 对节点给出相对优先级，优先深入最可能产生有价值方案的分支

优先级可参考：该节点离根本目的的关键程度、现有知识或资源是否支持
进一步细化、该分支是否尚未充分理解、用户特别关注的方案。
资源和约束只影响投入多少分析精力，不得在尚未分析前删除其他方案分支。

### 步骤 3：逐节点展开

队列非空时，取出优先级最高的节点。每次只展开当前节点的一层直接手段，
再将新节点放回队列。发现上层表述或拆分有问题时，允许回退修改。

#### 3.1 确认节点表述与角色

检查当前节点是否：

- 清晰、具体、原子化，不把多层目的手段关系塞进同一节点
- 在当前上下文中表述“要实现什么”或“以什么实现”，而非只是分类标签
- 没有把时间顺序、纯因果关系或主观理由误写成目的手段关系

对每一条边都可问：

> 完成右侧节点，是否直接为实现左侧节点提供手段？

若中间仍有更贴近左侧目的的子目的，应补上该层，不直接跳到具体方案。

#### 3.2 检查重复、共享与环路

先判断当前节点与已有节点是否实际是同一目的或同一手段，注意对象、
条件、阶段不同的相似表述未必等价。

- 只是偶然重复且后续展开一致时，标注 `：上方已分析` 或 `：下方已分析`
- 同一手段服务多个目的，或其子树对多个位置都有价值时，建立独立子树
- 当前节点等价于祖先节点时，标注 `：祖先节点已分析`
  并简要说明反馈或抑制关系，不再递归展开

共享手段的写法如下：

```markdown
* 实现目的 A
	* 手段 S：单独深入分析

* 实现目的 B
	* 手段 S：见“单独分析：手段 S”

# 单独分析：手段 S
* 手段 S
	* 子手段 1
	* 子手段 2
```

独立子树是原树的阅读重构，不表示手段只服务于标题上方的一个目的。

#### 3.3 寻找直接手段

先找当前目的最直接的手段或子目的，而不是一步跳到过细的实现细节。
手段链的节点类型不同，合适的展开方式也不同。优先使用下列思路：

1. 若目的可由定义、公式、必要条件或明确的组成关系刻画，先用它拆出条件
2. 若要改变属性状态，可列举能产生该状态的工作原理或方案大类
3. 若手段是构造某个对象、映射或系统，可拆其必要的结构、性质、
   参数选择或实现过程
4. 若手段是输入输出变换、测量或评判，可拆输入、输出、所用原理、
   评判准则或实现机制
5. 若以上均不合适，再按问题的逻辑构成直接拆分

更详细的节点类型与展开范式见 `references/expansion-patterns.md`。
在类型不明确、拆分顺序不唯一或需要寻找方案宽度时阅读它。

不要把“所有手段都必须列全”当作硬性要求。对开放方案空间，
应优先列出有区分度的方案大类，并在高价值分支继续细化。

#### 3.4 确定组合关系并检查跳步

在写入前判断同层手段的关系：

- And：各项共同构成当前目的的实现条件
- Or：任一方案分支可独立作为实现路径
- +、×：关系有明确的定量含义时才使用

若一个复杂结构同时包含 And 和 Or，不要把不同逻辑混写在同一组兄弟节点。
补出一个中间子目的或方案节点，使每个父节点的同级关系清楚。

检查每个子节点是否直接服务父节点。它不必单独保证父目的完全实现，
但应在当前上下文中承担可解释的、非跳步的作用。

#### 3.5 判断暂止节点

满足下列任一情况时，可在行末标记 `：暂止（理由）`，不再加入队列：

- 已具体到当前分析的目标粒度，继续展开只会变成无关实现细节
- 继续展开需要用户作价值选择或另行决策
- 已达到自然规律、外部标准或当前不能改变的边界
- 继续展开需进入另一项独立分析
- 当前分支优先级很低，暂不值得投入更多精力

“暂止”不表示该手段不可再分析，而是说明本次分析在此停下的理由。

#### 3.6 写入子节点并更新队列

拆分清楚后：

1. 在父节点后写入组合关系标记
2. 写入一层直接子节点，不顺手写更深层
3. 为每个子节点评估优先级，加入待展开队列
4. 每完成若干节点或一个主要子树，及时落盘

### 步骤 4：中期结构扫描

每新增约 20 到 30 个节点，或完成一个主要分支后，检查：

- 是否存在跳步、角色混淆或不清楚的 And／Or
- 同一手段是否被重复展开，是否应改为独立子树
- 独立子树的文字回指是否准确，是否遗漏它服务的其他目的
- 是否有祖先回指形成的反馈关系，且标注是否说明其含义
- 是否有优先级低但被过度细化，或优先级高却尚未展开的分支
- 是否有过深或过于复杂的子树，应单独分析

### 步骤 5：收尾复盘

当高优先级节点均已展开或合理暂止时，至少做两轮复盘。每轮逐项检查：

1. 节点是否清晰、原子化，并在上下文中保持目的或手段角色
2. 每条边是否为直接目的手段关系，是否存在跳步
3. And、Or 与其他组合关系是否准确、没有混写
4. 是否有应继续展开的高价值节点，或本应暂止的低价值细节
5. 已知的重要方案、论文方法或用户提出的候选方案，能否在链中找到合理位置
6. 共享手段、独立子树、祖先回指和反馈标注是否前后一致
7. 是否有其他不合理、前后矛盾或不利于使用结果讨论方案的地方

若某轮发现问题，立即修正后重新从检查一开始。连续两轮无修改，
或只剩用户明确决定暂不展开的分支时，分析完成。

## 输出格式规范

### Markdown 文件结构

```markdown
# 目的手段链分析：[目的概括]

* 根本目的
	* 直接子目的或直接手段
		* 下一层手段
	* 可替代方案：or
		* 方案 A
		* 方案 B

# 单独分析：共享手段
* 共享手段
	* 子手段
```

### 缩进表示规则

- 所有节点以 `* ` 或 `- ` 开头
- 每一层增加一个 Tab
- 不使用编号
- 子节点在当前上下文中实现父节点
- 连续唯一子手段可使用 `←` 简写压平，但只有在不会掩盖组合关系时使用

## 与用户互动

- 根本目的理解不确定时先确认
- 分析可能分成多个独立根目的时先说明并确认
- 对范围、资源、成本、风险等信息，默认不提前限制手段空间
- 用户要求只分析既有方法时，保持封闭，不擅自扩展成完整方案库
- 用户要求探索替代方案或从头设计时，主动展开有区分度的候选方案大类

## 开始分析

当用户请求目的手段链分析时：

1. 确定根本目的和当前使用场景
2. 需要时阅读场景和展开范式参考
3. 创建 Markdown 分析文件与待展开队列
4. 逐节点展开，检查表述、关系、重复、共享和暂止条件
5. 定期做结构扫描，必要时抽出独立子树
6. 完成两轮收尾复盘后交付分析结果
