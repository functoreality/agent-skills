# 内容与呈现检查

在事实、论证、引用、说明结构或最终呈现影响交付质量时查阅。
按产物用途选择检查，不默认把所有文本都改造成面向初学者的说明书。

## 事实与来源

优先核对支撑主要结论、操作决定和明显争议的事实。
对引文、数字、方法归属或来源声称，回到原始材料查看上下文，
确认来源确实支持当前表述及其适用条件。
搜索摘要、先前总结或另一个 agent 的结论不能替代必要的原文核对。
关键句混合多个事实时，拆开核对各项是否都获支持，避免部分正确掩盖其余错误。
同时检查关键声明是否缺少支持，以及所附引用究竟支持了哪一部分。
多个来源可以共同支持一个结论，但主题相关或链接存在本身并不足够。
多个转载同一上游的材料不能当作多份独立证据。

区分原始材料中的事实、自己的推断与尚未验证的假设。
检查归纳是否扩大了来源的证据范围，是否把相关性写成因果，
是否省略了足以改变结论的条件、反例或不确定性。
对容易变化的信息，按任务要求和工具规则核实有效时间，
不把历史资料自然视为当前事实。

来源无法访问或证据不足时，缩小结论或明确保留不确定性，
不要补写未经查证的支持材料。

## 推理与语义一致性

检查核心推理的前提、关键过渡与结论是否衔接。
可用简单反例、极端但适用的情况，或换一种独立推导检验结论。
这些检验用于发现具体问题，不要求为每段文字构造完整形式证明。
优先找出真正决定结论的一两项前提，尝试替代解释或改变该前提，
看结论是否会逆转，再决定核查重点，不机械制作完整假设矩阵或计分。

注意跨段、跨文件及图文之间是否使用相同定义、单位、范围和版本。
例如正文声称支持某场景，操作说明或实现却不支持，
不能只修正文案就认为问题已经解决。

在方案或分析中，核对推荐结论是否仍对应用户目标，
比较是否基于一致的前提，重要代价和限制是否被隐藏。
不为让论证更漂亮而替用户更改目标或价值取舍。

## 阅读与使用路径

从目标读者会带着的实际问题出发，检查能否找到、理解并使用答案。
重点查看必要前提是否可获得、信息顺序是否支持操作或决策，
指代、术语和结论是否足够明确。

读者已有的领域知识可以作为合理前提，
需要依赖作者对话记忆才能理解的信息则应检查是否缺失。
避免为消除每一种潜在误解而加入大量重复说明，
也不要因内容“都写到了”就忽略读者是否找得到。

需要独立视角时，按 [独立评审](independent-review.md) 选择视角并设置隔离。
需求与专业准则核验者可以对照原始资料核实，
读者审阅者不接收创作准则与作者辩解。

## 渲染、导出与交付完整性

当布局、分页、图表或交互呈现影响使用时，检查用户实际会打开的最终产物。
仅检查源文件或生成脚本不足以发现裁切、溢出、缺字、错位或导出丢失。

- 核对与本次变化相关的页面、区域及典型长短内容。
  有代表性的抽查需覆盖不同布局或边界状态，不把抽查写成全量检查。
- 图表除外观外，还需核对数据、坐标、单位、图例和正文结论是否一致。
- 多文件交付应确认入口、资源和引用可用，
  从接收者拿到的实际目录或包验证，避免依赖作者机器上的偶然路径。
  核对预期附件与实际文件是否匹配，必要时检查传输或版本混杂。
  文件齐全、校验和一致与内容可用是不同结论，不能相互替代。
- 修订会改变布局或生成物时，重新生成并查看受影响部分，
  确保交付的是最新导出物。
  下游验证应对应实际上游产物，而非未经说明的人工替代样例。

报告、notebook 或导出文件可能保存失败前的部分结果，
需确认执行范围及错误状态，不能以“文件生成了”推断整个任务完成。

使用任务已有的格式处理工具或相关领域 Skill 完成必要检查。
无法渲染、打开或验证的部分如实说明，不以源文件可解析替代实际呈现证据。
