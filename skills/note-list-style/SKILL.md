# 清单体 Markdown

## 适用范围

- 读者—面向人：供人阅读的 Markdown 默认用清单体，包括新写、重整以及人与 AI 共用的文档。
- 文体—按需适配：用户指定的文体、项目约定和该文档类型的明确专用指令优先。连续论述、叙事或逐字引用可保留段落或引用块。
- 局部编辑：先读邻近条目，按该节要回答的问题归位和改写。沿用周围的术语和层级，再和父项及邻项一起读。
	- 口径：统一术语或指标前，核对定义、单位和统计口径。
- 持续维护：随反馈、新证据或项目变化更新。同口径的新证据优先并入原处，再复核受影响的结论。
	- 批量增补：一起看新旧条目，找出可合并、对比或重新归组的内容。
	- 详情复用：长期维护的详情多处用到时，可选一处写全。其他位置保留当处需要的结论，并链接到详述。

## 组织正文

- 用途—先定读者：想清楚谁会读、要拿来做什么、会用多久。快速同步重扫读，反复查阅重定位和追溯。
- 答案—优先呈现：先给读者最需要的结论、决定或用法。证据不足时交代目前能确定什么。
- 主线—跟随用途：按文档用途组织；原顺序便于理解或回查时可以沿用。
	- 过程—还原经过：按需要还原的过程选组织方式。
		- 事件：按时间线还原。
		- 指南：按实际操作步骤写。
		- 案例：按情境、目标、行动和结果组织。
	- 调研：按问题、要素或对比维度组织。
	- 方案：按目标、约束和取舍组织。
	- 实验：按发现和适用条件组织。
	- 解题：按问题、限制、做法和结果组织。
	- 分析：从事实归纳规律和判断，选用或提炼贴合问题的框架。
- 背景—就近交代：把理解所需的信息放在读者需要的位置。
	- 做法：先说明要解决的问题和直接做法，再补细节。
	- 前提前置：会决定读者能否采用的前提放在做法前。
	- 术语与指代：在首次需要时解释术语。容易混淆的指代就近点明对象。
- 标题—提示答案：已有可靠结论时写明对象和发现，尚未确定时可写待回答的问题。
- 导读—长文按需：提供要点或目录，方便读者回到对应章节。

## 分组与缩进

- 范围—先整体拆：复杂文档先划定范围，再拆章节。同级主题围绕同一问题，保持颗粒度相近。
- 同级—尽量六项：同一个无序或有序列表中，**直接并列项尽量不超过 6 个**。
	- 分类—不重不漏：有 7 项或更多时，优先按读者能辨认的同一维度做 MECE 分组，在当前范围内做到不重不漏。
	- 缩进—按类挂入：将类别作为同级条目，把原条目缩进到对应类别下。增补时先找最贴近的已有类别。每个子列表也按同一原则复查。
	- 比较关系补层：几条内容有共同类别且各有实质区别时，可用该类别补一层。
	- 平铺例外：逻辑上需要连续平铺时可保留，例如分组会打断理解的事件时间线。
- 父子—概括与支撑
	- 父项—统括范围：行首及其后的正文共同界定所有子项的范围。
	- 子项—展开细节：每条解释一个从属要点，如该范围内的证据、原因、步骤或例外。
	- 并列规则—另列：父项正文若含与子项并列的独立规则，将它移为同级子项。
	- 关键条件：把**会改变判断的条件**和结论放在同一条里。
	- 并列关系：容易混淆时，说明并列子项是备选做法，还是要同时满足的条件。
- 深度—常三层内：简单内容用一层列表，复杂内容通常用两到三层。
	- 薄层归并：零碎的单项子层可收回父项。
	- 降层数—深层独立：可改成小节或链接到附录。
	- 降层数—改子标题：原顶层要点改写为 Markdown 标题，从而可整块减少缩进。
- 列表—按关系选：并列信息用无序列表，有实际先后的步骤或排名用有序列表。

## 写条目

- 信息点—保持独立：每项只表达一个独立信息点。共同界定同一判断的细节可放在一起。
- 取舍—按用途判断：依据回看和行动需求决定保留哪些内容。先取舍，再拆独立要点。
	- 保留：足以理解和核实的对象、结论、理由、约束、数字与单位、风险和关键例子。
	- 行动：交代已有共识、下一步、责任人和期限，标出待确认事项。
	- 压缩：去掉不影响理解和行动的重复、寒暄、插话、空泛修饰和枝节。
- 行首—短语加冒号：优先用 `主题—概述：细节`。常用读者回查时会找的对象或问题作行首。完整判断、条件和理由留在冒号后。
	- 标点—禁令变通：明确禁用冒号时，可用中点 `·` 分隔，如 `主题—概述·细节`。
	- 字数—常六字内：主题和概述分别尽量在 6 字内。两到四字能辨认就够，少数可放宽到 8 至 10 字。
	- 精简—先压再省：太长时先精简措辞（如「纠正错误」→「纠错」）或删次要信息。某段仍超 10 字时可省掉该段，把含义留在正文，成为 `主题：细节` 或 `概述：细节`。
	- 短句例外：加行首会重复或妨碍理解时，可以直接成句。
	- 同组对齐：尽量统一行首格式和颗粒度，方便扫读和重排。父项已交代统一主题维度时，子项可只写能帮助定位的差异。
	- 主题复用：同一主题可配不同概述重复出现，方便并排扫读；并列项较多时仍按含义分组。

	```markdown
	- 发布—合并部署：评审通过的修改合并到主分支后，由流水线构建并发布手册。
		- 发布异常：流水线通知值班维护者。
	- 预览—外部访问截止：周五关闭外部访问权限，团队成员仍可打开预览链接。
	- 暂缓网页编辑：有同事需要频繁修改手册且**无法使用仓库**时，再评估可视化编辑器。
	- 周末暂停例行发布。
	```

- 标记—突出重点：用常见 Markdown 格式表达结构和重点，换平台后仍能读出关系。
	- 强调：行首可用普通文字，需要强调时优先在句中标出关键条件或结论。
	- 状态：用 `【待确认】` 等标记表达含义明确的状态。
	- 标签：行末按需加 `` `#需复核` `` 等标签，便于视觉辨识或跨条目查找。
	- 索引：需要自动索引时，沿用阅读工具的标签语法。

## 呈现比较和证据

- 比较—先明维度：交代比较对象和维度。
	- 维度：差异能独立变化、交叉组合时，分维度表述。每个维度内横向比较各可能性。
	- 定性：交代差异、取舍和依据。
	- 量化：写出指标和单位；描述变化时写清参照、方向和幅度。
- 汇总—交代范围：说明证据覆盖范围，保留影响判断的例外、缺失信息和条件差异。
- 归因—核对变量：单项归因需要相应对照，多个变量同时变化时按整组条件描述观察。
- 表格—服务比较：用于比较或复核可比字段。
	- 位置：放在对应判断之后。
	- 共享条件：在正文交代。
- 来源—区分性质：区分观察、来源的说法、自己的推断和待验证事项。整组性质一致时可在父项注明，混排时逐条标明。
	- 转述：保留来源的适用条件和确定程度。改名或重分类影响回查时，注明与原材料的对应。
	- 评注：放在所评内容旁，写清依据和影响。
- 回查—直达依据：需回查的判断就近链接到直接依据。
	- 链接说明：用链接文字或邻近说明交代它是证据、实例还是延伸材料。
	- 引用范围：子项新增判断时给出对应依据。整组共用来源时写明覆盖范围。
	- 原文概括：精确措辞会影响解释时，可先概括，再就近按需用引用块附关键原文及出处。

## 交付前复核

- 核验—扫读定位：看标题、浅层条目和各级条目的行首，若找不到关键信息，把对应要点提到上层。
- 结构—核对层级
	- 同级内容：复查同级条目是否重叠或遗漏关键范围。
	- 父子关系：试着略过子项，确认父项仍能交代本层判断或所问的问题。再核对子项是否都在该范围内。
	- 同级数量：遇到 7 项或更多时优先分组，保留连续平铺的合理例外。
- 行长—常百字内：连读文本通常控制在 100 个可见字符内。合并源码软换行，显式换行两边分别计数。
	- 保留例外：拆短会损害理解的单一要点可以保留。
	- 短条目：同样复查是否混入了独立判断。
- 长行—按关系处理
	- 压缩：同一要点有冗余时，精简重复和修饰，保留必要信息。如「如果测试没有发现问题，在获得两位负责人批准后即可进行发布」→「测试未见问题且二负责人批准后可发布」。
	- 并列拆分：包含多个独立要点时，拆成同级条目，默认均加能区分同级内容的短行首。
	- 父子拆分：结论附带证据、原因或步骤时，父项写清结论或范围。细节缩进为子项，按需加行首。
	- 组合拆分
		- 同级子项：并列要点需共用主题、前提或范围时，将它们列为同一父项的同级子项。
		- 父项行首：通常只写行首。确需交代共同前提或总览时，在冒号或中点后补一句覆盖全部子项的导语。
- 检查器—按需提示：从 skill 目录运行，按需复核篇幅、并列项数量和行首。
	- 篇幅：默认提示超过 100 字符的标题或段落，包括列表内文字；跳过表格、代码块和原始 HTML 块。
	- 同级：`--max-siblings 6` 提示同级超过六项的列表；分类质量和平铺例外由作者判断。
	- 行首：`--check-prefix` 逐条识别冒号或中点。行首缺失且行长超 20，或行首短语超过 6 字时给出低优先级提示。
	- 开关：行首提示默认关闭，也可用 `--no-check-prefix` 明确关闭。

	```bash
	python3 -m pip install markdown-it-py
	python3 scripts/check-length.py --max-siblings 6 path/to/document.md
	python3 scripts/check-length.py --limit 120 path/to/document.md
	python3 scripts/check-length.py --max-siblings 6 --check-prefix path/to/document.md
	```
