## 论文概要

Chop（Chain of Operators）将冻结的 In-Context Operator Network（ICON）用一条「前置算子链 F → 冻结 ICON → 后置算子链 G」包装，把 OOD 目标算子 T 重构为 ICON 可靠的归纳算子 T'，无需更新参数；算子链由 LLM agent 进化搜索（EvE）发现，所有变换为闭式解析操作（值归一化、坐标平移、守恒律投影、残差迁移），并在推理时用 in-context 交叉验证决定是否启用链。

### 1. 零参数解析算子链重构 OOD 目标算子 — 优先级：中

**概述**：论文核心机制是 `F → Icon → G` 链（§3.1-3.2，式 5-11）。F 和 G 由闭式初等算子复合而成：值归一化（affine scaling）、坐标对齐（cyclic shift）、守恒律 L2 投影（mass projection）、留一残差迁移（residual transfer）。每个算子无常数可训参数，所有变换常数从 prompt 数据即时算出。这与 AOT-POT（可学线性变换层）和 ARC-STAR（可训后处理网络）形成鲜明对照。

**手段链**：
获得 ICON 可靠区外的算子预测 ← 把 OOD 目标算子 T 重构为归纳算子 T'（ICON 对 T' 可靠）← 在 prompt 侧施加显式变换 F 并在预测侧施加 G 还原 ← 用闭式解析算子复合构造 F 和 G（值归一化、坐标对齐、对称作用） ← 从 prompt 数据即时估计变换常数（均值、方差、位移量）

**类型**：已有目的的新手段。「让任务适配冻结模型」这一目的在笔记中已有 AOT-POT（AISClit9.md L193-225，可学变换层）和 ARC-STAR（冻结主模型+后处理修正网络）作为先例。Chop 的手段新颖点在于：(a) 变换链完全零参数、闭式，(b) 前置变换+后置逆变换+约束投影的完整三段式结构，(c) 进化搜索而非手工设计或梯度学习发现链。

**三要素评估**：
- **新颖性：中**。笔记中「算子变换简化目标」策略类别（AOT-POT, AISClit9.md L193-225）已存在；「冻结主模型+外挂修正」策略（ARC-STAR, AISClit9.md L132-192）也已存在。但 Chop 的「零参数闭式算子链」是这两类策略的交叉实例，且其「前置变换+逆变换」的对称结构与 ARC-STAR 的「纯后处理」和 AOT-POT 的「内嵌变换层」在机制上不同。笔记中 data.md L453 记录的 `(x,x')→y-y'` 参考样本改写是零参数变换，但仅是单一改写而非可复合链。
- **实用性：高**。零参数闭式变换可迁移到任何「冻结 backbone + OOD 适配」场景（不限 ICON、不限 PDE）：只要目标算子存在已知结构对称性（守恒律、周期性、缩放不变性）就可构造投影/对齐算子。残差迁移机制可推广到任何有上下文示例的少样本推理场景。
- **非平凡性：中**。值归一化和坐标对齐是常规预处理（笔记 NOarch.md L434 框架 `o1le7k` 已有「改写映射输入输出形式」的通用框架）；但将「守恒律 L2 投影」作为 rollout 误差漂移校正的显式步骤，以及「留一残差迁移」作为上下文相似度加权的误差校正，两者具有一定非平凡性。

### 归因

这些改动同源：**专家在写标题前，脑中先浮现了一个具体的检索场景；AI 没有这一步**。

专家先推演：一年后我回到笔记系统，我脑中的问题是什么？大概是"ICON 遇到预训没见过的算子怎么办？要微调吗？有没有更简单的办法？"然后标题直接回答这个问题——告诉未来的自己：不需要微调，在输入输出上做简单变换就行，简化后就可靠了。

AI 写标题时想的是：这篇论文做了什么？冻结 ICON、外挂算子链、把 OOD 映射回可靠 regime。这是在**描述方法的组成部分**，用论文自己的框架词（OOD、regime、重构）来组织。这种标题对"刚读完论文的自己"来说能看懂，但对"一年后忘了细节、带着问题回来检索的自己"来说，每个词都需要解码。

这不是单个原子改动的归因，是一组改动共享的同一个根源：**场景预演的缺失**。

**执行失败**：AI 读到了但没有真正执行"设想未来你带着什么问题回来查"。这步跳过去了，直接进入"这篇论文做了什么"的描述模式。
